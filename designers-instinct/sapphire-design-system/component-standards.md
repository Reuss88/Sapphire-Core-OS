# Component Standards

## Principle
Components are commercial instruments, not decoration. Every reusable component must have a clear semantic role, data contract, interaction contract and accessibility contract.

## Core families
- application shell and workspace navigation
- command header and global search
- attention, action and inbox summaries
- market signal and profile cards
- commercial metric and value cards
- tables, queues and timelines
- forms, approvals and irreversible-action confirmations
- AI briefing and evidence panels
- drawers, modals, command palette and notifications
- charts and geographic intelligence surfaces

## Card standard
Cards use matte surfaces, fine borders, restrained elevation and 16–24px internal spacing. A card must declare title, semantic state, freshness, ownership and drill-down where applicable.

The shared Card frame owns the approved polished-chrome opposing-corner bezel and optional restrained header/focus gradient. Pages select documented variants; they do not recreate bezels, pseudo-elements or gradients locally.

## Controls
Primary actions use Royal Sapphire. Destructive or irreversible actions never use primary blue. Status chips remain compact and textual. Icon-only controls require labels and tooltips.

## Tables
Tables prioritise scanning, pinned identity columns, explicit units, stable alignment and keyboard navigation. Dense mode is allowed. Responsive tables become prioritised record cards or horizontal data surfaces rather than unreadable compression.

## Forms
Forms expose required evidence, validation timing, save state and authority. Financial, contract and governance forms require explicit confirmation and server-returned result states.

The live component system must include complete field, selection, date/time and calendar patterns so forms remain patchable from one source. Calendar controls expose timezone, keyboard navigation and touch-safe targets.

## AI surfaces
AI is presented as Sapphire Intelligence, not a generic chatbot. AI components show evidence, confidence, freshness and limits. Suggestions must route into authorised actions rather than silently mutate records.
