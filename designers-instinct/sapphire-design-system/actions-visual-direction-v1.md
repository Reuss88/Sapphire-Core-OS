# Actions Visual Direction v1

## Status

Director-approved Sapphire visual doctrine, 8 August 2026.

## Governing decision

The approved Actions execution canvas is the current visual and interaction direction for Sapphire Core OS.

The live Sapphire Design System must be extracted from and improve upon Actions. HOME and every later workspace must consume that system. Older page references remain useful for their commercial content, information hierarchy and page-specific composition, but they do not override the Actions-derived shell, density, material, controls or interaction language.

Where an older HOME instruction conflicts with this direction, use the following precedence:

1. current Director instruction;
2. this Actions visual direction;
3. shared Sapphire Design System doctrine;
4. page-specific commercial doctrine and composition;
5. older page imagery and implementation details.

## Visual laws derived from Actions

- Dense, calm and execution-first rather than ceremonial or dashboard-like.
- A thin collapsed desktop rail reveals full navigation as an overlay and never pushes the workspace.
- Compact command headers replace oversized page introductions.
- Primary work occupies the centre and receives the largest useful area.
- Surfaces use matte graphite/navy material, fine separators and restrained elevation.
- Sapphire blue identifies selection and primary action; gold is reserved for commercial attention and premium emphasis.
- Cards and panels are aligned working surfaces, not a mosaic of competing decorative tiles.
- Controls remain compact on desktop and become at least 44px on touch surfaces.
- Information density is created through hierarchy, alignment and typography, not tiny illegible text.
- Drawers and sheets preserve context on narrower screens.
- Motion is controlled, functional and reduced-motion safe.

## Approved material evolution

- Shared premium card frames use subtle polished-chrome highlights on opposing corners.
- Headers and focused working regions may use restrained background gradients.
- Chrome and gradients are material treatments only. They never replace semantic status, evidence, freshness or authority labels.
- All treatments are design-system variants and may not be recreated in page-local CSS.

## HOME application

HOME keeps its doctrine-defined executive questions and its commercially required regions. It must, however:

- use the Actions-derived shell and overlay navigation;
- use the same command-header proportions and control families;
- use the same typography, spacing, surfaces, borders, selected states and responsive behaviour;
- use shared card variants rather than the older page-specific card styling;
- match Actions' calm density and avoid the older permanent 224px sidebar;
- remain recognisably the HOME command deck while clearly belonging to the same application as Actions.

The approved HOME image is therefore a content, hierarchy and broad composition reference—not an authority to reintroduce visual language that conflicts with Actions.

## Governance

New workspace patterns are first added to the live design system, documented and validated, then consumed by pages. A page may not fork a shared component merely to reproduce an older image.
